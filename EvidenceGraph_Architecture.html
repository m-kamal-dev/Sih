EvidenceGraph

An agentic validation layer that sits beside the AICTE approval portal. Agents gather and propose evidence, versioned rules decide, and authorised officials make every adverse call. Every finding links back to the page, the rule and the source that produced it.

8agents plus two human checkpoints
4 + 1stores: Postgres, Neo4j, Qdrant, MinIO, plus Redis
6verification statuses, exactly as the PS lists them
0adverse decisions taken without an officer

01Design principles

Each principle answers a question the jury will ask. Every component below follows from these.

Facts carry provenance

Every value records its document, page, bounding box, extractor, confidence and the date it was true (as_of).

Models extract, rules decide

LLMs read and explain. A compliance outcome only comes from a versioned rule that cites its handbook clause.

No finding without evidence

The Critic drops any finding whose evidence pointer does not resolve to a stored crop and fact.

Never fabricate verification

If an issuer cannot be reached, the status is pending or source_unavailable, and the case goes to a person.

Suspicious is not forged

Anomaly signals, potential discrepancies and confirmed violations are kept as separate classes. Only officers escalate.

Augment, don't replace

A standalone service with a portal adapter. No live AICTE integration is claimed, and no restricted database is assumed.

03Application lifecycle

What happens from upload to an officer's decision. The agent graph runs per application; heavy steps fan out per document.

flowchart LR
  A[Submission or self-check] --> B[Ingest and render]
  B --> C[Intake and planner]
  C --> D[Doc reader]
  C --> E[Forensics]
  C --> F[Source verifier]
  D --> G{Confidence gate}
  G -- low confidence --> H[[Officer corrects field]]
  H --> I[Cross-check]
  G -- confident --> I
  E --> I
  F --> I
  I --> J[Compliance engine]
  J --> K{Critic}
  K -- evidence missing, once --> I
  K -- pass --> L[Reporter]
  L --> M[[Officer decision]]
  M --> N[(Audit ledger)]
  1. Submission event. The portal adapter receives a webhook or pulls a batch. During the self-check, the institution uploads through the same API.
  2. Ingest. Each file is hashed (SHA-256), scanned with ClamAV, and its MIME type is checked against its extension. qpdf strips JavaScript and embedded files. Pages are rendered at 300 DPI, deskewed and denoised. Duplicates are skipped by hash.
  3. Intake. The application category and session select checklist@version. A completeness diff produces completeness_gap findings straight away, before any model runs.
  4. Parallel fan-out. The Doc reader, Forensics and Source verifier run per document as Celery tasks. The supervisor waits on all of them.
  5. Confidence gate. Fields below a per-type threshold pause the graph with a LangGraph interrupt. An officer confirms or corrects the value. The correction is stored as a new fact version with source = human.
  6. Cross-check. Entities are resolved, written to Neo4j, and compared on matching dates. Cross-institution queries run against the whole session.
  7. Compliance. Versioned rules run over the fact set. Each returns pass, fail, or insufficient evidence.
  8. Critic. Checks every finding for resolvable evidence, a valid rule reference, contradictions and neutral wording. It sends work back once, then escalates to a human.
  9. Reporter. Builds the report checklist by checklist, computes a triage score, drafts the deficiency letter with clause citations, and raises alerts.
  10. Officer decision. The officer accepts, dismisses or escalates each finding, with a mandatory reason. Every action is written to the hash-chained ledger and becomes labelled data.

04Agents

Each agent has a narrow job, typed inputs and outputs, a fixed tool list, and a guardrail. Most of the work is done by deterministic tools; the LLM fills gaps.

Intake and planner rules

Works out what this application has to prove.

Inputs
Application JSON, category, academic session
Tools
Checklist registry, prior-records adapter (previous EoA, approved intake, TER status)
Outputs
Task plan (document → checks), completeness findings for missing, extra or mis-slotted uploads
Guardrail
Fully deterministic. The LLM only helps classify a free-text request when the category is ambiguous, and an officer confirms the result.

Doc reader models + LLM

Turns uploads into facts with coordinates.

Inputs
Page renders, embedded text layer, document slot
Tools
Layout classifier, PaddleOCR and an Indic OCR model, Table Transformer or Docling for tables, LLM with JSON-schema decoding per document type
Outputs
Facts with page, bbox, confidence and as_of. Values are normalised: dates, areas (acre, hectare, sq m), currency, names
Guardrail
Grounding check: each LLM-extracted value must overlap OCR tokens on the cited bbox, otherwise its confidence is capped. Document text is treated as untrusted data.

Forensics tools

Collects authenticity signals. Never issues verdicts.

Inputs
Original file bytes, renders, detected stamp and signature crops
Tools
pikepdf (incremental updates, producer and dates), pyHanko (DSC chain, changes after signing), text-layer vs OCR diff, font inventory, pyzbar QR decode, copy-move and ELA, Qdrant near-duplicate lookup
Outputs
anomaly_signal findings with a strength (strong, medium, weak) and the evidence crop
Guardrail
The word "forged" never appears. Weak signals alone cannot raise severity above low.

Source verifier connectors

Checks documents against the issuer, where a route exists.

Inputs
Document type, identifiers, QR payloads, signed PDFs
Tools
Connector registry (section 11) with retries, rate limits and a circuit breaker
Outputs
VerificationResult: source, reference ID, timestamp, field-by-field match, one of the six statuses
Guardrail
Never infers verified. Mock connectors are labelled "mock" in the UI and the database. QR URLs are fetched only from allowlisted issuer domains.

Confidence gate human

Stops a blurred digit from becoming a mismatch.

Trigger
Field confidence below its type threshold (identifiers stricter than names)
Action
LangGraph interrupt. The officer sees the crop and the value, then confirms or corrects
Outputs
New fact version with source = human. The original is kept and marked superseded
Why
Keeps extraction confidence separate from the regulatory outcome, as the dossier asks

Cross-check graph

Finds where documents and records disagree.

Inputs
Facts from the form, documents, prior records and issuers
Tools
Identifier-first matching, then trigram blocking and Splink probabilistic linkage, Indic transliteration, Neo4j pattern queries
Outputs
potential_discrepancy findings that show every conflicting value with its date and source
Guardrail
Values are compared only for the same date. Ambiguous entity matches go to review instead of being merged automatically.

Compliance engine rules + CV

Applies the handbook, version by version.

Inputs
Resolved fact set, rulepack@APH-edition
Tools
YAML rule evaluator, infrastructure vision: photo reuse, EXIF date and GPS, room-type classifier, floor-plan area extraction
Outputs
Pass, fail or insufficient evidence for each rule. confirmed_violation only when every input is verified or human-confirmed
Guardrail
Vision output is always advisory and can only request more evidence or an inspection.

Critic quality gate

The reason the report can be trusted.

Checks
Evidence resolves to a stored crop. Rule and version exist. No two findings contradict. Wording is neutral (no "fraud", no "fake")
Action
Drops or downgrades failing findings. Sends work back to Cross-check once, then routes to a human
Outputs
Explainability coverage: the share of findings with full evidence and a rule. This becomes a headline metric

Reporter LLM

Writes for the scrutiny officer, not for the model.

Inputs
Findings that passed the Critic, checklist, APH clauses retrieved from Qdrant
Outputs
Validation report grouped by checklist item, a triage score with reasons, a deficiency letter draft citing clauses, alerts
Guardrail
Only drafts. Nothing is sent to an institution until an officer approves it.
Why a graph and not a chain. The Doc reader, Forensics and Verifier are independent, so they run in parallel per document. Only Cross-check needs all three. The Critic loop and the two human interrupts need a state machine with checkpoints. That is what LangGraph with a Postgres checkpointer provides, and it also gives replayable runs for audit.

05Data layer

Each store does the one thing it is best at. Postgres holds the truth. Neo4j and Qdrant are projections fed by a transactional outbox, so they can be rebuilt from scratch at any time.

PostgreSQL truth

Relational integrity and audit.

Holds
Applications, documents, facts (versioned), rules, findings, verification attempts, reviews, audit ledger, LangGraph checkpoints
Why
ACID transactions, row-level security by region and assignment, mature backups, JSONB for flexible fact values

Neo4j relationships

Questions that span institutions.

Holds
Entity layer (institution, trust, faculty, land, FDR, signatory, stamp, photo) and evidence layer (fact, page, rule, finding)
Why
Multi-hop pattern queries like "same faculty, two colleges, same session" are a few lines of Cypher and slow, deep joins in SQL

Qdrant similarity

"Have we seen this before?"

Holds
APH clause text, page text, stamp and signature crops, infrastructure photos, extraction examples
Why
Named vectors with payload filters (session, institution, doc type) keep searches scoped. HNSW is fast at any scale this needs

MinIO blobs

Originals and evidence.

Holds
raw/ with object lock (WORM), pages/, crops/
Why
S3 API, server-side encryption, short-lived presigned URLs for the console. Blobs stay out of the databases

Redis transient

Work in flight.

Holds
Celery broker, connector rate-limit counters, short-lived caches
Why
Nothing here is the system of record, so it can be lost without losing data

Sync pattern outbox

How the stores stay consistent.

Write
Fact or finding insert plus an outbox row in one transaction
Project
A worker reads the outbox, runs MERGE in Neo4j and upserts in Qdrant, keyed by event ID
Recover
Replay the outbox from zero to rebuild both projections

06Schemas

PostgreSQL core tables

CREATE TABLE documents (
  id uuid PRIMARY KEY, application_id uuid REFERENCES applications,
  checklist_slot text, doc_type text, doc_type_conf real,
  sha256 char(64) UNIQUE, object_key text, page_count int,
  uploaded_at timestamptz, status text);

CREATE TABLE facts (
  id uuid PRIMARY KEY, application_id uuid, document_id uuid,
  key text,                 -- e.g. land.total_area, faculty.count
  value jsonb, value_norm jsonb, unit text,
  page int, bbox real[4], extractor text, confidence real,
  as_of date,               -- the date the source says this was true
  recorded_at timestamptz DEFAULT now(),
  superseded_by uuid,       -- officer corrections create a new version
  source text CHECK (source IN ('form','document','record','issuer','human')));

CREATE TABLE findings (
  id uuid PRIMARY KEY, application_id uuid, region text,
  rule_id text, rule_version int, aph_ref text,
  finding_class text CHECK (finding_class IN ('completeness_gap','validity_gap',
    'potential_discrepancy','anomaly_signal','confirmed_violation')),
  severity text, confidence real, summary text,
  status text DEFAULT 'open',   -- open | accepted | dismissed | escalated | rectified
  created_by text);              -- rule:<id> | agent:<name>

CREATE TABLE finding_evidence (finding_id uuid, fact_id uuid, crop_key text, role text);

CREATE TABLE verification_attempts (
  id uuid PRIMARY KEY, document_id uuid, connector text, ref_id text,
  requested_at timestamptz, responded_at timestamptz,
  status text CHECK (status IN ('verified','mismatch','expired','pending',
    'source_unavailable','manual_review')),
  field_matches jsonb, response_digest char(64), is_mock boolean);

CREATE TABLE audit_log (
  seq bigserial PRIMARY KEY, at timestamptz DEFAULT now(), actor text,
  action text, entity text, entity_id uuid, payload jsonb,
  prev_hash char(64), hash char(64));   -- hash = sha256(prev_hash || canonical(row))

ALTER TABLE findings ENABLE ROW LEVEL SECURITY;
CREATE POLICY by_region ON findings USING (region = current_setting('app.region'));

07Findings and status model

Two independent axes. What kind of problem it is, and what the issuer said. Merging them is how systems end up calling a blurry scan "fake".

Finding classMeaningCan be raised by
completeness_gapA required item is missing, unreadable or in the wrong slotIntake
validity_gapThe document has expired, or expires before the session startsCompliance
potential_discrepancyValues disagree across form, documents or records and need an explanationCross-check
anomaly_signalForensic or similarity indicator. Preliminary onlyForensics, Qdrant lookups
confirmed_violationA deterministic rule failed on verified or officer-confirmed inputsCompliance, with officer acceptance
Verification statusWhen
verifiedThe issuer returned a record and every compared field matched
mismatchThe issuer returned a record and at least one field differs
expiredThe issuer record exists but is no longer valid
pendingThe request was sent and no answer has arrived yet

08Rules as code

Every handbook requirement becomes a YAML file with its clause reference, inputs, logic, messages and test cases. A new APH edition means a new rule pack, and old applications can be re-run against it.

id: EOA.FIRE_NOC.VALIDITY
version: 3
aph_ref: "APH 2024-27, §[take exact clause from handbook]"
applies_to:
  categories: [EOA, INTAKE_INCREASE, NEW_PROGRAMME]
  sessions: ["2026-27"]
inputs:
  - { fact: fire_noc.valid_until, min_confidence: 0.90 }
  - { fact: session.start_date }
assert: "fire_noc.valid_until >= session.start_date"
on_fail:
  class: validity_gap
  severity: high
  message: "Fire NOC expires on {fire_noc.valid_until}, before the {session} session starts."
on_insufficient_evidence: { route: field_review }
tests:
  - { name: valid,       facts: { fire_noc.valid_until: 2027-06-30, session.start_date: 2026-08-01 }, expect: pass }
  - { name: lapses_early, facts: { fire_noc.valid_until: 2026-07-15, session.start_date: 2026-08-01 }, expect: fail }

Rule types to cover in the prototype. Presence (the item is in the checklist), validity (date in range), threshold (a numeric norm from the APH), cross-document equality with tolerance (form vs deed), and temporal consistency (the faculty count on the form matches the roster as of the same date).

Do not invent norms. Every threshold, ratio and clause number must come from the actual APH text. Wherever the team has not confirmed a clause, leave the [fill in] marker in the rule file and say so in the demo. Judges respect that more than a confident wrong number.

MATCH (p:Person)<-[e1:EMPLOYS]-(i1:Institution),
      (p)<-[e2:EMPLOYS]-(i2:Institution)
WHERE i1.aicte_id < i2.aicte_id AND e1.session = e2.session
  AND e1.from <= coalesce(e2.to, date()) AND e2.from <= coalesce(e1.to, date())
RETURN p.faculty_id, i1.aicte_id, i2.aicte_id, e1.source_doc, e2.source_doc

// Recycled land parcel
MATCH (l:LandParcel)<-[:OWNS|LEASES]-(t1:Trust), (l)<-[:OWNS|LEASES]-(t2:Trust)

RETURN f.bank, i1.aicte_id, i2.aicte_id

12Security, privacy and governance

Present it as an institutional system, not an upload demo. This section is where a cybersecurity-minded team can stand out.

RoleCanCannot
Institution applicantUpload, run self-check, see its own report, respond to deficienciesSee forensic internals, other institutions, triage scores
Scrutiny officerReview assigned applications, correct fields, accept, dismiss or escalate findingsChange rules, see other regions' data
Senior reviewerDecide escalations, approve deficiency lettersEdit the audit ledger
Rule administratorAuthor and test rule packs, which publish only after a second approvalAct on applications
AuditorRead the ledger, replay runs, export reportsChange anything

Untrusted documents

Uploads are attacker-controlled input.

Files
ClamAV, MIME sniffing, qpdf sanitisation, size and page limits, rendering in a sandboxed worker with no network
Prompts
Document text is passed to the LLM as data only. The extracting model has no tools. Output must match a JSON schema. Text that looks like instructions to a model is itself raised as an anomaly_signal
SSRF
QR and reference URLs are fetched only from allowlisted issuer domains, through an egress proxy

Data protection

Aligned with the DPDP Act, 2023.

Access
Keycloak OIDC with MFA for officials, Postgres row-level security by region and assignment
Crypto
TLS 1.3 and mTLS between services, MinIO server-side encryption, salted hashes for identifiers, raw Aadhaar never stored
Models
On-prem inference only. No document goes to an external AI service
Retention
Configurable per document class, with purpose limitation and logged downloads

Tamper-evident audit

The ledger proves its own integrity.

Chain
Each row stores the hash of the previous row. Any edit breaks every hash after it
Anchor
A signed daily digest of the head hash is stored outside the database
Replay
Checkpoints, rule versions and model versions are logged, so any finding can be reproduced

Human authority

Built into the code, not just the policy.

Letters
The system cannot send anything to an institution. Only an officer action can
Escalation
confirmed_violation needs an officer acceptance with a reason
Wording
The Critic blocks accusatory terms in every generated text

13Reviewer console

The screen judges will remember. Build it around one officer clearing one application quickly.

Queue

Applications ordered by triage score, each with its top three reasons, SLA timer and open-item counts. Filter by category, region and status.

Evidence split view

PDF.js on the left with bounding boxes highlighted. Extracted facts and findings on the right. Clicking a finding jumps to the exact page and region.

Conflict view

The same fact from form, documents, prior records and issuers in one row, each with its date and source, so the officer can see whether a date explains the gap.

Graph view

Neighbourhood of an entity drawn with Cytoscape.js. For example, a faculty member and every institution that lists them this session.

Verification timeline

Each connector call with status, timestamp and reference ID. Mock sources are labelled.

Decision bar

Accept, dismiss or escalate with a required reason. Draft deficiency letter with clause citations, editable before approval.

Institution self-check

The applicant sees a fix list (missing items, expiring documents, form and document mismatches) before submitting. No forensic details are exposed.

Metrics board

Precision, recall, verification coverage, explainability coverage and time per application, computed live on the test set.

15Deployment and scale

# docker compose services for the demo (single GPU machine)
gateway      api        supervisor   worker-ocr  x2   worker-forensics
worker-verify  projector  vllm (GPU)   vision (GPU)   console
postgres     neo4j      qdrant       minio       redis    keycloak
clamav       grafana    langfuse     mock-issuers
  • Scale by document, not application. OCR, forensics and verification workers scale horizontally. Tasks are keyed by SHA-256, so retries never duplicate work.
  • Peak season. The portal adapter supports batch pulls with backpressure, and the triage score lets the riskiest applications reach officers first.
  • GPU budget. One node serves vLLM and the vision models. Most pages never reach the LLM, because OCR plus schema templates resolve them.
  • Integration path. Standalone service first, then a read-only adapter for a pilot regional office, then deeper integration subject to AICTE's security review. Kubernetes manifests mirror the compose services.

18Pitch and jury questions

Slide storyline

  1. AICTE's job. Thousands of institutions, many documents each, category-specific rules that change by edition.
  2. The gap. The layers exist separately (OCR, forensics, KYC, DigiLocker). Nothing joins them around AICTE's rules with evidence.
  3. EvidenceGraph. The architecture diagram, and one line: agents gather, rules decide, officers rule.
  4. Live demo. The six-minute script.
  5. Safeguards. Two-axis status model, Critic, human gates, on-prem models, tamper-evident ledger.
  6. Results. Measured numbers on the test set, with their limits stated.
  7. Rollout. Self-check first (no risk to AICTE), then a read-only pilot with one regional office.

Questions to rehearse

What if the AI is wrong?

It cannot take an adverse action. Low-confidence values go to a person first, the Critic removes unsupported findings, and every flag shows its evidence. Our false-positive rate on clean controls is on the metrics board.

Do you have access to AICTE's data?

No, and we don't assume it. Every source sits behind an adapter. The demo uses synthetic records and labelled mock connectors with the same schema as the real ones.

Why three databases?

Postgres is the truth and the audit. Neo4j answers questions across institutions that are impractical in SQL. Qdrant finds reused seals, photos and templated pages. Both projections can be rebuilt from Postgres.

Regional languages?

Indic OCR models, multilingual embeddings and transliteration-aware name matching. Low-confidence regional text goes to the confidence gate instead of being guessed.

Can't a good forger beat ELA?

Yes, which is why ELA is ranked as a weak signal. The strong signals are issuer verification, signature checks and cross-document and cross-institution inconsistencies, which editing a single image cannot hide.

Privacy?

On-prem models, role-based access with row-level security, hashed identifiers in the graph, encryption, logged downloads and configurable retention, aligned with the DPDP Act.

What happens when the handbook changes?

A new rule pack version, tested with its own fixtures. Old findings keep their rule version, and past applications can be replayed against the new pack.

Could a document manipulate your LLM?

Document text is data only. The extracting model has no tools and must return a fixed schema. Injected instructions are flagged. We show this live.
